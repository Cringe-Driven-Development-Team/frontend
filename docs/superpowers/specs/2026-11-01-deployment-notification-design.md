# Итоговое уведомление о выкатке: задачи, PR и Health Check

Задача: [frontend#131](https://github.com/Cringe-Driven-Development-Team/frontend/issues/131).
Статус: дизайн ожидает подтверждения владельца.

## Цель

По итоговому уведомлению CD/Rollback должно быть понятно, какие задачи изменились,
прошла ли проверка прода и какие PR посмотреть. Один выпуск может включать несколько PR
и задач; случайный первый PR не представляет весь выпуск.

## Подходы

- Неограниченный набор кнопок PR: простой переход, но неудобное большое сообщение
  и риск ограничений Telegram.
- Одна кнопка полного отчёта всегда: компактно, но добавляет переход даже для одного PR.
- Выбран владельцем: до шести кнопок PR по две в строке; при большем числе PR —
  одна кнопка «Все PR выпуска», ведущая на полный список со ссылками.

## Поведение

- Длинный успешный абзац «Этот запуск: проверен…» заменяется строкой `Health Check ✅`.
  При `failure` — `Health Check ❌`, при `skipped`, `cancelled` или отсутствии
  результата — `Health Check ⚪`. Результат берётся из настоящего шага Health check,
  независимо от общего статуса job. Этап сбоя и сведения о неподтверждённом
  переключении сохраняются при ошибках; зелёная отметка не означает постоянный мониторинг.
- Вместо первых коммитов показывается раздел «Задачи»: уникальные названия связанных
  issues со ссылками. Для PR без закрывающей связи показываются его название и ссылка.
  Связи берутся из GitHub, номера задач не угадываются по названиям веток или коммитов.
- Состав определяется фактической разницей версий: при CD — добавленные PR, при Rollback —
  удалённые PR; раздел отката называется «Отменённые задачи». Используется существующая
  логика определения принадлежности PR выпуску и закрывающих связей, без новой модели данных.
- Один PR: кнопка «PR». От двух до шести: кнопки «PR #N», по две в строке;
  нечётная последняя кнопка занимает отдельную строку. Более шести: только
  «Все PR выпуска». Кнопки прод/откат/логи сохраняются, кнопка сравнения «Изменения» убирается.
- Полный перечень PR и связанных задач со ссылками записывается в Summary текущего
  CD/Rollback run. Кнопка «Все PR выпуска» ведёт на этот run с `#summary`.
- Порядок PR — по возрастанию номера; повторяющаяся задача показывается один раз.
- PR нет: явная строка «Связанных PR нет», без кнопки PR. Прямые коммиты не теряются:
  сравнение версий остаётся ссылкой в полном отчёте, без выдуманной задачи.
- При переполнении бюджета сообщения Telegram сокращается только список задач;
  добавляется ссылка на полный отчёт. Результат, Health Check, SHA и управляющие кнопки
  остаются доступны. Слишком длинное название сокращается с сохранением ссылки.
- Ошибка чтения GitHub не выдаётся за пустой список: текст «Состав изменений недоступен».
  Отправка результата выкатки продолжается, в логах остаётся предупреждение;
  неполный отчёт явно помечается. При неизвестной предыдущей версии состав не угадывается.

Решения о размещении отчёта в Actions Summary, обработке пустого состава, ошибках,
порядке и сокращении списка предложены агентом и входят в подтверждаемый дизайн.

## Границы и проверка

Изменяются итоговые уведомления CD и Rollback, их тесты и документация.
Уведомления очереди, публикации и начала выкатки сохраняются.
Не меняются механизм выкатки, статусы доски и уже отправленные сообщения.

Проверки: все исходы Health Check; 0/1/6/7 PR и нечётная строка; несколько задач
одного PR, общая задача нескольких PR и PR без задачи; разница версий в обе стороны;
длинный список, экранирование названий и недоступность GitHub. Перед PR —
`bun run check`, релевантные тесты, `bun run build` и actionlint при правке workflows.

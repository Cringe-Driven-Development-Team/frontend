# Синхронизация реализованных экранов с макетом Figma (#52)

## Зачем

Макет в Figma обновлён. Источник правды — плагин, который его генерирует:
`Design/cellestial-plugin-v1/cellestial-plugin/code.js`, версия `v33`. Сайт местами отстал
от макета: тени, отступы, тексты на луне, ширина колонки ячеек. Задача — довести до
макета то, что **уже реализовано**, чтобы следующие задачи по новым экранам начинались
с совпадающей базы.

## Цели

Привести к v33 существующие токены, компоненты и экраны «01. Вход», «02. Регистрация»,
«03. Блокноты», «04. Блокнот» в части, которая уже есть в коде.

## Не цели

- Новые фичи и экраны из макета: поиск (SearchField, SearchBar, SearchHighlight), запуск
  ячеек (RunButton, ToolButton, SaveStatus, гуттер ячейки, Output), загрузка .ipynb
  (Dropzone, кнопка «Загрузить», модалка Upload), профиль (AvatarLarge, пункт меню
  «Профиль», страница), состояние кнопки Primary / Disabled.
- Новые токены, которые нужны только этим фичам: `primary-soft`, `text-disabled`,
  `highlight`, `highlight-current`, `code/string`, `code/comment`.
- Описание StateBlock «Блокнотов пока нет» в макете упоминает .ipynb — текст не меняем,
  загрузки ещё нет.

## Анти-цели

- Нельзя трогать то, чего нет в макете, но что есть в коде, — решение заказчика, оставить
  как есть:
    - кнопка удаления у ячейки;
    - чипы «+ Код / + Текст» под списком ячеек;
    - заглушка «Блокнот не найден»;
    - тост `info` («Вы вышли из аккаунта»).
- Нельзя менять поведение (валидация, запросы, роутинг) — кроме подсветки полей при
  ошибке входа, которая описана ниже.
- Без новых библиотек (правило AGENTS.md).

## Что меняется

### 1. Токены — `styles/tokens.css`

Тени из стилей эффектов макета (радиус Figma = blur в CSS):

| Токен                         | Значение                                                                                                   |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `--shadow-glow-primary`       | `0 8px 24px -10px rgb(124 92 255 / 0.55), inset 0 1px 0 rgb(255 255 255 / 0.35)`                           |
| `--shadow-glow-primary-hover` | `0 10px 28px -8px rgb(140 110 255 / 0.7), inset 0 1px 0 rgb(255 255 255 / 0.45)`                           |
| `--shadow-popover`            | `0 12px 32px rgb(0 0 0 / 0.6), 0 0 32px 2px rgb(139 108 255 / 0.28), inset 0 1px 0 rgb(255 255 255 / 0.1)` |

Новые токены:

- `--code-keyword: #b79bff`, `--code-number: #ffc98a` (в макете `code/keyword`,
  `code/number`). Заменяют захардкоженные цвета в `NotebookCard.module.css`.
- `--blur-glass: blur(20px)` — стиль эффекта «Glass / Blur» (в макете радиус 40;
  в Figma радиус размытия фона примерно вдвое больше CSS-значения — **наш выбор**,
  сверить на глаз со скриншотом макета).

### 2. Стеклянное размытие

`backdrop-filter: var(--blur-glass)` там, где в макете стоит «Glass / Blur» и фон
полупрозрачный. У Header в макете тоже Glass / Blur, но фон непрозрачный
(`--color-surface-solid`) — размытие ничего не изменит, поэтому Header не трогаем
(**наш выбор**).

- NotebookCard в обычном состоянии и скелетон (на hover макет меняет эффект на
  Elevation / Popover — у нас это уже `box-shadow: var(--shadow-popover)`, размытие
  на hover можно оставить);
- StateBlock.

### 3. Вход и регистрация — `pages/AuthPage/`

Геометрия карточки:

- Половины карточки **равные** (в макете обе FILL). Сейчас 544 / 452 — заменить на 50 / 50,
  в том числе в расчёте `transform` луны (`calc(100cqw * 544 / 996)` и
  `100cqw * 452 / 996`).
- Луна: внутренний край ровно по середине карточки, диаметр такой, чтобы круг накрывал
  оба внешних угла своей половины. При карточке 996 × 560 это **660 px**
  (формула из плагина: `r ≥ (w² + h²/4) / 2w`, w — ширина половины, +2 px). Размер
  фиксированный 660, а не вычисляемый по ширине — **наш выбор**: карточка ограничена
  `max-width: 996px`, а на узком экране своя раскладка. Кратеры и градиенты масштабируются
  вместе с луной (`Moon` нарисован в 600 × 600 — масштабировать через `transform: scale`
  или отдельный размер, на усмотрение исполнителя).
- Узкий экран (`max-width: 860px`) не трогаем: луна там остаётся 600 px с прежним
  положением — мобильных экранов в макете нет (**наш выбор**). Значит, 660 px задаётся
  только в десктопном `.moon` в `AuthPage.module.css`, а не в `Moon`.

Лицевая сторона луны (`face`):

- Заголовок и текст — блок с отступом 8 px, от него до кнопки — 24 px
  (сейчас всё через `gap: 16px`).
- Текст: стиль Caption, цвет `--color-on-light`, по центру, ширина 300 px, без
  принудительных переносов (`white-space: pre-line` убрать).
- Тексты:
    - на входе (зовёт регистрироваться): «Cellestial — блокноты с Python прямо в браузере.
      Пишите код и заметки в ячейках, запускайте их и сразу видите результат. Ничего не
      нужно устанавливать.»
    - на регистрации (зовёт войти): «Войдите, чтобы вернуться к своим блокнотам. Код и
      заметки сохраняются автоматически — продолжите с того места, где остановились.»

Ошибки:

- «Неверный логин или пароль» (`invalid_credentials`): красная рамка у **обоих** полей,
  сообщение — только под паролем, под логином строка пустая. Нужно, чтобы `Input` умел
  показывать состояние ошибки без текста — способ (отдельный проп вроде `invalid`
  или иное) выбирает исполнитель; `aria-invalid` при этом ставится.
- `login_taken`: текст остаётся «Логин уже занят. Выберите другой». В макете — «Этот логин уже
  занят. Войдите или выберите другой», но в однострочной строке под полем он обрезается
  многоточием на телефоне и при окне уже ~1200 px; решение заказчика — короткий текст.

### 4. Модалки — `components/Modal`, `LogoutDialog`, `CreateNotebookDialog`

- От заголовка до описания — 8 px (макет: блок Head, gap 8). Сейчас между заголовком
  и описанием в «Выйти из аккаунта?» 24 px. От шапки (заголовок + описание) до
  следующего блока остаётся 24 px.
- Между кнопками действий — 12 px (сейчас 8) в обеих модалках.

### 5. StateBlock

- Между кнопками — 12 px (сейчас 8). Исключение из макета: в пустом блокноте чипы
  «+ Код / + Текст» идут через 8 px. Как передать разницу — на усмотрение исполнителя
  (например, `className` у actions или проп).

### 6. Блокнот — `pages/NotebookPage/`

- Колонка ячеек — 792 px (8 колонок сетки), по центру контента 1200 px. На ширине
  меньше 792 — на всю доступную ширину.
- Между ячейками — 24 px (сейчас 32).
- Чипы под списком ячеек, скелетоны и StateBlock (пусто / не найден) — в той же колонке
  792 px. StateBlock уже ограничен 792 px.

## Ограничения

- Правила AGENTS.md: CSS Modules, короткие camelCase-классы, JSDoc на экспортах,
  алиасы импортов, без внешних библиотек.
- Перед «готово» — `bun run check` и `bun run build`.
- `--shadow-popover` используют меню профиля, тосты, снекбары, модалки и карточка входа —
  новая тень с фиолетовым ореолом меняет их все (так задумано в макете). При визуальной
  проверке пройтись по каждому.
- Ветка `web-52`, PR в `Cringe-Driven-Development-Team/frontend` с `Closes #52`.

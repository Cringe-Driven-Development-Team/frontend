# BFF: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Рабочий BFF в `apps/bff`: Hono + tRPC под Bun, зашифрованная cookie-сессия, refresh,
CSRF, пользователь в первом HTML, образ и локальный Compose. Пишется под целевой контракт Go.

**Architecture:** Один процесс `Bun.serve` с приложением Hono. `/api/trpc` отдаётся официальному
`fetchRequestHandler`. Общий слой `session/` (cookie, refresh, клиент Go) используют и
`createContext`, и HTML-хендлер. Go вызывается сгенерированным Orval-клиентом через мутатор
`bearerFetch`. Для приёмки есть заглушка Go `apps/bff/dev/go-stub.ts`.

**Tech Stack:** Bun 1.4, Hono 4, `@trpc/server` 11, zod 4, `serialize-javascript`, Orval 8,
Turborepo, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-10-21-bff-design.md`. Требования — задача
[frontend#2](https://github.com/Cringe-Driven-Development-Team/frontend/issues/2), подробности —
страницы трека (contract, auth, service, bootstrap на docs.cellestial.ru/modules/2/tracks/bff).
Исполнитель читает все три источника.

## Review Focus

1. Батч из нескольких процедур, где первая сделала refresh: остальные идут с новым access, в ответе
   ровно одна `Set-Cookie` сессии с итоговым значением (задача 4, шаг проверки батча).
2. Cookie расшифровывается, но `refreshExp` уже прошёл: это отсутствие сессии с удалением cookie,
   Go не вызывается (задача 3).
3. Строки пользователя с `</script>`, `<!--`, ` `, кавычками, `&` и кириллицей восстанавливаются
   из bootstrap байт в байт (задача 5).
4. POST без `Origin`, с `Origin: null` или с `Origin` со слэшем на конце: `403 csrf_invalid`
   (задача 4).
5. Go отвечает 2xx с телом не того вида (текст или пустое тело у `users/me`): RPC — `BAD_GATEWAY`,
   HTML — 503, сессия не трогается (задачи 3 и 5).

**Files:**

**Interfaces:**
- Consumes: `env` (задача 2), Orval-функции (задача 1).
- Produces (`go/errors.ts`): `class GoError extends Error { kind: 'http' | 'network' | 'timeout' | 'unexpected'; status?: number; code?: string }`;
  `unwrap<T>(res: { status: number; data: unknown }, ok: number[]): T` — статус вне `ok` →
  `GoError('http')` с `code` из тела `Error`, если оно есть; статус из `ok`, но тело не того вида
  (для JSON-ответов: не объект или массив) → `GoError('unexpected')`. `bearerFetch` переводит
  `AbortError`/`TimeoutError` в `GoError('timeout')`, прочие ошибки `fetch` — в `GoError('network')`.
- Produces (`session/crypto.ts`): `type SessionData = { access: string; refresh: string; accessExp: number; refreshExp: number }` (unix-секунды);
  `sealSession(data: SessionData): Promise<string>`; `openSession(value: string): Promise<SessionData | null>`.
  AES-256-GCM через `crypto.subtle`, ключ — `env.sessionKey`, IV — 12 байт `crypto.getRandomValues`
  на каждый вызов, `additionalData` — UTF-8 имени cookie, формат `base64url(iv ‖ ciphertext‖tag)`.
  Любая ошибка разбора, расшифровки или формы JSON → `null`.
- Produces (`session/cookies.ts`): `SESSION_COOKIE = '__Host-Http-session'`;
  `readSessionCookie(req: Request): string | undefined`;
  `sessionCookie(value: string, maxAge: number): string`;
  `clearedSessionCookie(): string`; `clearedLegacyCookies(): string[]` — `access_token` с
  `Path=/api/v1`, `refresh_token` с `Path=/api/v1/auth`, `__Host-csrf` с `Path=/`, все
  `Max-Age=0; Secure; HttpOnly`. Атрибуты сессии — `HttpOnly; Secure; Path=/; SameSite=Lax`, без
  `Domain`.
- Produces (`session/refresh.ts`): `class SessionEnded extends Error`;
  `refreshTokens(refresh: string, requestId?: string): Promise<SessionData>`. Одновременные вызовы
  с одним refresh получают один промис, ключ — hex SHA-256. Успешный результат держится 10 с после
  завершения, неудача из кеша удаляется сразу. 401 от Go → `SessionEnded`, остальное → `GoError`
  (S2S в том числе).
- Produces (`session/session.ts`): `createSession(req: Request): Promise<Session>`.
  `Session` реализует:
  - `readonly active: boolean`;
  - `start(tokens: TokenPair): Promise<void>` — новая сессия после login/register;
  - `end(): void` — пометить cookie к удалению;
  - `call<T>(fn: (init: RequestInit) => Promise<T & { status: number }>): Promise<T & { status: number }>` —
    без сессии бросает `SessionEnded`; при `accessExp − now < 30` сначала refresh. Ставит
    `Authorization: Bearer` и `X-Request-ID` (из входящего запроса, иначе `crypto.randomUUID()`).
    На 401 от Go — refresh и один повтор, повторный 401 → `end()` и `SessionEnded`. `SessionEnded`
    из refresh тоже вызывает `end()`. `GoError` сессию не трогает;
  - `setCookies(headers: Headers): void` — идемпотентно приводит `Set-Cookie` сессии к текущему
    решению: новая, удаление или ничего. Чужие `Set-Cookie` сохраняет;
  - `clearLegacy(): void` — добавить к ответу `clearedLegacyCookies()`.
  
  Если cookie не расшифровалась или `refreshExp <= now`, сессии нет и она помечена к удалению
  (Review Focus 2). Значения `maxAge` берутся из `refresh_expires_in`; для сессии из refresh —
  `refreshExp − now`.
- Produces (`go/api.ts`): `createGo(session: Session): Go`, где
  `Go = { getCurrentUser(): Promise<User>; listNotebooks(): Promise<NotebookSummary[]>; getNotebook(id: number): Promise<Notebook>; createNotebook(body: CreateNotebookRequest): Promise<Notebook>; createCell(id: number, body: CreateCellRequest): Promise<Cell>; deleteCell(id: number, index: number): Promise<void>; logout(): Promise<void> }`
  — каждый метод: `session.call(init => orvalFn(…, init))` и `unwrap` с успешными статусами из
  спеки. `publicGo = { register(body): Promise<{ user: User; tokens: TokenPair }>; login(body): Promise<{ user: User; tokens: TokenPair }> }`
  — без сессии, только с `X-Request-ID`.
- Браузерные `Cookie`, `X-CSRF`, `Authorization` в Go не уходят: `init` собирается с нуля, входящие
  заголовки не копируются, кроме `X-Request-ID`.
